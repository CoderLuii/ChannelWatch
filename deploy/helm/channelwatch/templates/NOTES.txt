Thank you for installing ChannelWatch.

ChannelWatch is deployed as a single replica only. Do not scale this release above one pod: the application persists shared state under /config and does not support concurrent writers.

Access the UI after the pod starts:

  kubectl get pods -l app.kubernetes.io/instance={{ .Release.Name }} -n {{ .Release.Namespace }}
  kubectl port-forward svc/{{ include "channelwatch.fullname" . }} 8501:{{ .Values.service.port }} -n {{ .Release.Namespace }}

Then open:

  http://127.0.0.1:8501

The pod remains NotReady while no DVR is configured or an enabled DVR monitor is degraded. The single-replica Service publishes that pod address by default so the setup and diagnostics UI stays reachable; pod readiness remains available as a monitoring signal.

PVC details:

  Mount: /config

Secret-backed values:

  - ChannelWatch creates and manages its encryption key under the persistent /config volume. No storage-key Secret is required for a new installation.
  - Set either secretConfig.existingSecret or the chart-managed secretConfig fields for optional bootstrap/provider credentials.
  - secretConfig.secretStorageKey is deprecated and exists only to migrate a v0.9.5-v0.9.17 legacy envelope once. Remove it after ChannelWatch reports successful migration.
  - secretConfig.apiKey is exposed to the container as CW_API_KEY; the entrypoint seeds it during the first /config/settings.json bootstrap.
  - secretConfig.adminUser/adminPass are exposed as CW_ADMIN_USER/CW_ADMIN_PASS; the UI backend bootstraps the first RBAC admin when RBAC is enabled and no users exist yet.

Upgrade note:

  ChannelWatch stores persistent settings, its managed encryption key, logs, backups, and runtime state in /config. Keep and protect the PVC when upgrading or reinstalling.
