# How to use Help & Feedback

Open **Help & Feedback** from the utility section of the ChannelWatch navigation. Choose the path that matches what you need.

## Report a problem

**Report a problem** opens the same secure workflow available from Diagnostics. It can prepare sanitized diagnostics, accept optional screenshots and a ChannelWatch debug bundle, and separate public issue text from private contact details and attachments.

Review the preview before submission. A proof timeout or network failure leaves the draft and attachments in page memory so you can retry. Nothing is stored in browser storage.

## Request a feature or change

The feature form asks for:

- a short title;
- what should change;
- why it would help;
- a product area;
- an optional screenshot;
- optional contact information.

Feature requests do not include diagnostics, logs, DVR inventory, client details, credentials, or a debug bundle. A failed submission keeps the draft and screenshot in page memory. Cancel closes the form without discarding it. Use **Discard draft** and confirm only when you want to clear it.

The public request excludes private contact information, attachment details, proof material, client addresses, and server metadata. Contact information and attachments remain on the private intake path.

## Ask a question

The page links to the ChannelWatch documentation, the Channels Community thread, and GitHub Discussions. These links open another site in a new tab and send no local ChannelWatch data.

## Privacy boundary

Drafts remain only in memory for the current page session. A successful submission or confirmed discard clears the draft. Reloading or navigating away also clears it. ChannelWatch does not place feedback drafts in localStorage, sessionStorage, IndexedDB, logs, metrics, or telemetry.
